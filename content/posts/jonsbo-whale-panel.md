## 写在前面

机箱上那块乔思伯 DS339 副屏，买回来新鲜了三天，之后一直循环播放官方的默认主题——一个转圈的风扇动画，和一张永远不变的 CPU 温度。

它其实是一块 960×376 的小屏幕，通过 USB 连接，由 **JONSBO AIO** 这个 Windows 软件管理。官方主题商店里选择不少，但都不太"属于自己"。

真正让我动手的是另一件事：我每天用 DeepSeek Harness（下称 DSH）写代码，它工作时、需要我确认时、问我问题时，都只发生在屏幕里。**如果副屏能变成它的状态灯呢？** 不用切窗口，抬眼看一眼机箱就知道"它在干活"还是"它在等我"。

于是有了这个项目：一块会动的鲸鱼娘副屏，同时是 DSH 的状态显示器。

成品、代码和文档都已开源：[wujiangyyo/jonsbo-whale-panel](https://github.com/wujiangyyo/jonsbo-whale-panel)（MIT）。

![待机状态](/goke-tech-blog/img/whale-panel-idle.png)

## 目标

一开始定的需求很具体：

- **待机**：时钟 + 会动的角色，不要静止图
- **工作中**：一眼看出"在跑什么"
- **待审批 / 等你回答**：必须醒目，最好能一直挂着直到我处理
- **不打断**：不能每换一次状态就重启软件、点一次鼠标

最后一条是最难的，也是整个方案的分水岭。

## 第一步：搞清楚这块屏是谁在画

副屏本身是个"哑设备"——它只负责显示软件推过去的画面，没有自己的逻辑。所有渲染都在 JONSBO AIO 里完成，再通过 USB 送出去。

我先试了官方提供的显示 SDK：能枚举到设备，推帧接口也返回成功，但屏幕始终没反应。这条路走不通，只能换个思路——**既然软件自己会画，那就让它画我想要的东西。**

JONSBO AIO 支持**自定义主题**：一个主题就是一个文件夹，里面有 `Setting.txt`（图层定义）、若干图片、一份 JSON 元数据。用户可以在主题列表里选它。

于是问题变成：**主题里的图片，是加载一次就缓存，还是每帧都重新读？**

试了一下——**每帧都重新读**。这就是整个方案的突破口。

## 三个关键发现

摸清楚之后，规则其实很简单：

**1. 图片资源是逐帧重读的。**
换掉主题目录里的 `data.png`，画面立刻变，不用重启、不用重新应用主题。

**2. `source\` 下的副本才是软件真正读取的那份。**
根目录的 `data.png` 更像一个"变更信号"。只改其中一个，画面不会动；两个都改才稳定。所以播放器每次写图要写两份：根目录用"临时文件 + 原子替换"，`source\` 直接写并带重试。

**3. 文字和图层结构只在"应用主题"那一刻读一次。**
这意味着没法靠改文字层做动态内容——动态的一切都必须是**图片**。这也是我最终自建一个"纯图片层"主题的原因：

```
name:WhaleGirl
width:960
height:376
data.png:x@0,y@0,z@-1
```

`z@-1` 表示最底层；因为没有别的图层，它实际就是整幅画面。

## 最终架构

```
┌──────────────┐  POST /state  ┌──────────────┐   cmd.json   ┌──────────────┐
│ DSH 桥接插件  │ ────────────▶ │ 本地 HTTP API │ ───────────▶ │  daemon.py   │
│ (浏览器侧)    │               │ :8765        │  原子写入     │  渲染 960×376 │
└──────────────┘               └──────────────┘              └──────┬───────┘
                                                                     │ data.png
                                                                     ▼
                                                      ┌────────────────────────┐
                                                      │ Programme/WhaleGirl/    │
                                                      │   data.png              │
                                                      │   source/data.png       │
                                                      └───────────┬────────────┘
                                                                  │ 逐帧读取
                                                                  ▼
                                                          ┌──────────────┐
                                                          │  JONSBO AIO  │
                                                          └──────┬───────┘
                                                                 │ USB
                                                                 ▼
                                                          ┌──────────────┐
                                                          │  DS339 屏幕   │
                                                          └──────────────┘
```

四个部件：

| 部件 | 职责 |
|---|---|
| **自定义主题** | 画布。一个只有图片层的主题，播放器往里写 PNG |
| **daemon.py** | 渲染器。10fps 循环，把"当前状态"画成一帧并写盘 |
| **本地 HTTP API** | 控制面。`/say` `/state` `/flash`，供外部调用 |
| **DSH 插件** | 遥控器。观察页面 DOM，把状态变化推给 API |

## 渲染：一帧是怎么画出来的

每一帧就三件事：**背景 + 角色 + 信息层**，必要时再加一层对话气泡。

- **角色**：从立绘素材里按状态选一张（待机轮播 18 个姿态，工作抱笔记本，审批待命，提问好奇）
- **信息层**：右侧卡片。待机显示大时钟；工作中/待审批/等你回答显示大号状态字 + 小时间
- **气泡**：竖排台词，跟着状态或动作变

关键优化是**只在画面真的变化时才重新编码写盘**：

```python
sig = (state, detail, pose, hhmm, bubble_text)
if sig == last_sig:
    time.sleep(0.15)
    continue        # 没变就不画
```

这一个判断把静态时的 CPU 从 12% 压到 **1% 左右**，内存稳定在 27–70MB。

另一个取舍：**状态切换用硬切，不做淡入淡出。** 一开始做了交叉淡化，结果在副屏上看起来像"重影"——两张图叠在一起的那半秒非常脏。硬切在小屏上反而干净利落。

## 状态从哪来

### 手动

```powershell
python say.py "开会中" "14:00-15:00 勿扰" 600
```

也可以直接 POST：

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8765/state -Method Post `
  -ContentType 'application/json' -Body '{"state":"approval","detail":"写文件权限"}'
```

### 自动：DSH 插件

DSH 的 Web UI 会在 DOM 上写一些语义标记，插件只读这些标记，不碰业务内容：

| DOM 锚点 | 含义 | 上报状态 |
|---|---|---|
| `[data-approval-key]` | 审批弹窗 | `approval` |
| `[data-question-key]` | 提问 | `question` |
| `[data-plan-review-key]` | 计划确认 | `plan` |
| `[data-chat-running]` | 会话运行中 | `working` |
| `[data-tool][data-state="running"]` | 工具执行中 | `working` + 工具名 |

优先级是 **审批 > 提问 > 计划 > 工作中 > 空闲**。审批和提问不设冷却，一直挂在屏幕上，直到我处理完。

插件还额外跟踪"工具从运行到结束"的转移，用来触发**瞬时气泡**：

- 工具正常结束 → `POST /flash {"kind":"success"}` → 三秒"搞定！"
- 出现错误标记 → `POST /flash {"kind":"failure"}` → 三秒"报错了…"

## 踩坑清单

下面这些坑，按"花了多久"排序。

### 1. 黑屏：`z@0` 不行

第一次自建主题，把图片层写成 `z@0`，结果屏幕全黑。改成 `z@-1` 并补一张 `back.png` 底色才正常。图层顺序上，`-1` 才是真正的底。

### 2. 花屏 / 重影

两个原因叠加：

- `source\data.png` 写入不是原子的，软件正好读到"写了一半"的文件；
- 状态切换用了交叉淡化，两张图叠加。

解决办法：**硬切 + 原子写**。根目录先写临时文件再 `os.replace`；`source\` 直写但带重试，失败就退回直接写。

### 3. 内存涨到 313MB

一开始为了让角色"会动"，做了旋转动画：每个角度都缓存一张精灵图。缓存很快吃掉了 300 多 MB。

后来砍掉了旋转，只保留有限的姿态切换，并把呼吸缩放量化到两位小数、缓存上限 40 张，内存回到 70MB 以内。

### 4. Emoji 变成方块

状态图标一开始用了 ⚠ ❓ 📋，在微软雅黑粗体里没有对应字形，副屏上显示成一排方块。

换成 `●` 加彩色文字就解决了。小屏幕上，**颜色比图标更有效**。

### 5. 气泡只弹一次就再也不弹

台词气泡"过期"后，我只让它不显示，但没有清空内部标记。于是后续判断一直认为"已经有气泡了"，冷却逻辑永远不触发。

修复只有两行：过期时把文本和 key 一起清空。**这类"状态残留"bug 在渲染循环里特别隐蔽**——画面看起来是对的，只是再也不更新。

### 6. 命令文件被并发写坏

插件和手动调用可能同时 `POST`，两个请求都用同一个临时文件名写 `cmd.json`，读端偶尔读到半截 JSON，日志里出现 `Extra data: line 1 column 56`。

改成 **唯一临时名 + 线程锁 + 原子替换** 之后再没出现。

### 7. 两个窗口互相覆盖

同时开了两个 DSH 窗口，插件跑了两份，一份发"终端"、一份发"pwsh"，画面来回跳。

先在播放器侧做了工具名归一化（把原始工具名映射成中文标签），两个来源发的东西一致了，抖动消失。彻底解决还是要只留一个窗口。

### 8. 播放器跟着 DSH 一起被杀

播放器最初是从命令行启动的，结果成了 DSH 的子进程——DSH 一重启，播放器也没了，副屏停在最后一帧。

改成用启动文件夹里的快捷方式（由 Explorer 拉起）或计划任务启动，脱离父子关系，之后重启 DSH 再也不影响它。

### 9. 竖排气泡的排版

这是迭代最久的部分，前后改了七八版：

- 横排 → 竖排（用户要"竖版"）
- 竖排两列 → 单列优先，排满 9 字才接第二列
- 列序从"从右往左"改成"从左往右"
- 标点不能出现在行首

最后定稿：**一字一行、先填满左列、溢出接右列、最多 18 字**。

### 10. 主次关系

状态字一开始只有 26px，和时钟抢不了注意力。后来改成：**状态字 58px 加粗，时间缩到 26px 并压到底部**。副屏本来就不大，一屏只能有一个主角。

**https://github.com/wujiangyyo/jonsbo-whale-panel**

顺手给项目点个 Star，让更多吃灰的副屏有个去处。

三步上手：

```powershell
# 1. 创建并注册自定义主题（然后重启 JONSBO AIO，在列表里选 WhaleGirl）
python whale\make_theme.py

# 2. 启动渲染器
python whale\daemon.py

# 3. 装 DSH 插件（可选，装了才有自动状态）
python bridge\install_bridge.py
```

立绘素材来自 [dsh-whale-musume](https://github.com/Sutera-Diffusus/dsh-whale-musume)（MIT），仓库只声明依赖、不打包素材。

## 局限

- 在软件里切换到别的主题，画面就会回到那个主题；播放器继续写文件，但不会自动切回来
- JONSBO AIO 升级后，资源读取方式可能变化，需要重新验证
- 只支持 Windows
- 状态接入依赖 DSH 的 DOM 标记，DSH 改版可能失效——好在只需改一个函数

## 结语

这个项目的核心其实不是"鲸鱼娘"，而是**把一块封闭的屏幕变成了可编程的画布**：只要找到"软件每帧都在读某个文件"这件事，剩下的就是写一个渲染器。

从"副屏吃灰"到"抬眼就知道 DSH 在干嘛"，中间隔着的不是技术难度，而是**愿不愿意为了一个小需求，把它的渲染链路摸清楚**。

如果你也有吃灰的副屏、小屏幕、LED 点阵，不妨看看它是不是也在默默读着某个文件。
