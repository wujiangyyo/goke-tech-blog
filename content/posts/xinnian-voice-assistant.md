# 给大模型装一副感官

晚上回家，对着客厅喊一声"新年，现在几点"。两秒后，角落里的旧手机听到了，一台小爱音箱用杨幂的音色回答你：现在是晚上十点。

"新年"是我给这套语音助手起的名字。它没有屏幕，没有 App，只有一个旧手机当耳朵、一台小爱音箱当嘴巴、一台服务器上的大模型当脑子。这篇文章写的是它怎么从一堆零件变成能听懂人话的东西。

## 为什么不用现成的智能音箱

市面上任何一台智能音箱都能回答"现在几点"。但我不想要它们，理由很具体：它的耳朵只听自家平台的指令，脑子是黑盒，数据出不去，也接不进我的知识库和工具链。我要的是一个能听懂"新年，看看我桌上是什么"然后真的去看的助手，现成音箱给不了。

于是决定自己搭。约束有一条：不能用玩具方案。语音助手必须跑在完整的 Agent 核心上，有记忆、有工具、能看图，跟我在终端里对话的是同一个脑子。这意味着不能写个"唤醒词+转写+固定回复"的脚本糊弄，那等于把核心扔了，只剩一个会答话的壳。

## 架构：一台旧手机，三样东西

整个系统跑在家里局域网，四台设备：

```
旧手机（android-ip-camera）
 ├─ 耳朵：原始麦克风流，经服务器灌进虚拟麦克风
 ├─ 眼睛：摄像头抓帧，缩小后交给视觉模型
 └─ 嘴巴：小爱音箱，DLNA 协议播报

服务器
 ├─ 拉流服务：手机音频 → 虚拟麦克风
 ├─ 语音合成：MOSS-TTS（本地，纯 CPU）
 ├─ Hermes CLI：唤醒 + 转写 + 大脑 + TTS
 └─ 另一台机器的 Ollama：qwen3-vl 视觉模型
```

调用链一句话：手机收音 → 唤醒词触发 → 语音转文字 → 大模型生成回答（必要时看图）→ 语音合成 → 小爱播报。

## 第一个难题：让唤醒词听懂中文

Hermes 内置的唤醒引擎默认只支持英文，中文短语喂进去直接报错。排查后确认是分词器的锅：内置模型全是英文 BPE token，中文字压根不在表里。

解决办法是给引擎打了个补丁：分词器支持拼音模式，模型换成 sherpa-onnx 的中文唤醒模型。改完以后"新年"两个字随时待命，喊"给新年"也能触发，因为"新年"在中间。

这个补丁有个代价：每次升级 Hermes 都会被覆盖，得重打。我在笔记里专门留了一节记这个。

## 第二个难题：让手机的声音变成服务器的耳朵

手机上的开源相机 App 会把麦克风流通过 HTTP 暴露出来。但 Hermes 不认网络流，它只认本地声卡。所以中间加了一层：服务器上用 ffmpeg 拉手机音频流，转成标准格式，灌进一个虚拟麦克风。从 Hermes 的视角看，它只是在听一个本地麦克风，手机在哪它根本不知道。

踩了两个坑。一个是手机有两条音频端点：处理过的和原始的。处理过的带降噪，但实测经常全静音，最后改用原始流，声音干净。另一个是录音的静音判定：阈值设得跟环境底噪一样高，结果 VAD 永远判断"还在说话"，录音停不下来。实测底噪数据后把阈值调到明显高于底噪，问题解决。

## 第三个难题：让小爱音箱开口说话

语音合成用本地部署的 MOSS-TTS，纯 CPU 推理。音色选了杨幂，对比了一圈：温柔晚安太轻、高冷御姐像老太太、邻家姐姐太怪，就杨幂最自然。自己克隆的音色也试过，远不如官方调教的。

音箱这边走 DLNA 推流：合成好的 mp3 放到本地 HTTP 服务，通过 UPnP 指令让音箱拉流播放。这里有个细节打磨了很久：什么时候发停止指令。发早了，音箱刚拉完流还没出声就被掐断；发晚了，音箱自动重播，你听到"一遍多一点"。最后方案是音频前后各加两秒静音做缓冲，播放固定延时后精确掐断，正好播完一遍干净收声。

## 眼睛：最后一个零件

视觉链路是最后接通的。手机摄像头抓一帧 4000×3000 的照片，交给 qwen3-vl 识别。实测发现 8B 视觉模型在普通机器上处理大图非常吃力：4K 原图根本跑不动，缩到 1024 要等三分钟，缩到 512 只要 45 秒。最后定了 512 方案，肉眼看清晰度够用。

关键是这套流程助手自己能走完。我问它"你现在能看到手机摄像头拍到的画面吗"，它自己加载技能、找到手机、抓帧、缩小、调视觉模型，然后准确说出我桌上那把雷蛇键盘的绿色背光。那一刻我觉得前面几天的折腾都值了。

## 踩坑精选

篇幅有限，挑三个最有代表性的：

**VAD 阈值不能拍脑袋。** 我一开始凭感觉设了 50，恰好压在环境底噪上，VAD 永远认为有人在说话，录音不停。老老实实录了一段音频逐秒算 RMS，才知道底噪在 40 到 51 之间浮动。阈值设 80，一次通过。

**音箱的"播一遍多一点"是 Stop 时机问题。** 小爱播完会自动重播，停止指令必须落在"第一遍播完、重播还没开始"的窗口里。试过轮询播放状态，音箱响应慢的时候轮询全超时，音频循环播了三遍。最后放弃轮询，用固定延时，稳。

**转写质量是最难啃的骨头。** 手机远场收音，环境声一多 whisper 就听岔。这个到现在也没完全解决，方向是物理层面的信噪比：手机放近一点，或者换带降噪的端点。

## 现在的状态

整套链路能跑：喊话、听懂、回答、播报、看图，全自动。生产形态做了 systemd 服务，开机自启，不用管终端。手机 App 和视觉模型那台机器按需开关，不影响日常。

还剩两件没做完：转写质量（远场收音的物理问题）和固定 IP（不然手机换地址了配置要跟着改）。都是工程收尾，不是架构问题。

说实话，这套东西没有一项技术是新的，ffmpeg、DLNA、whisper、视觉模型，全是现成的。真正的活是把它们接成一个完整的人，还要让它看起来不费劲。它现在还不算聪明，但它是我的，耳朵长在我家里，脑子长在我的服务器上。
