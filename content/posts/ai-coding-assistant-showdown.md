# ⚔️ 三强争霸：Codex vs pi vs DeepSeek Harness

## AI 编码助手测评实录（果壳科技 · 2026-08-19）

> 同一个命题、同一套方法论、同一台服务器——三个 AI 编码助手从零各做了一款产品。
> 本文记录完整过程、方法论、四维对比与踩坑实录。

---

## 一、背景：我们为什么要做这场测评

果壳科技（家庭实验室规模）在 Arch 服务器上跑着一套 AI 全家桶：Dify、n8n、Gitea、Ollama、密码管家……还有一位 AI「产品总监」莉莉（Hermes Agent），日常负责提需求、盯验收。

服务器上装了三个 AI 编码助手，日常都可以用来写代码：

| 选手 | 驱动 | 定位 |
|---|---|---|
| 🤖 **Codex**（OpenAI Codex CLI） | DeepSeek V4 Pro | OpenAI 官方 CLI，老牌稳重 |
| 🥇 **pi**（pi-coding-agent） | DeepSeek V4 Pro | 轻量高效，DeepSeek 驱动 |
| 🆕 **DSH**（DeepSeek Harness） | DeepSeek V4 Pro | DeepSeek 官方 Agent 框架（2026-08-13 开源，GitHub 史上最快涨星） |

**问题**：谁更强？谁更省？谁值得长期用？

---

## 二、方法论：三次实验的进化（核心！）

### R1：需求文档极其详细 → 两版一模一样

第一轮，莉莉写了**极其详细的需求**：布局图、风格参考（「深蓝底 + 青色点缀」）、每个模块怎么排。

**结果：Codex 和 pi 做出来的东西几乎一模一样**——功能相同 + 视觉锁死，差异只剩代码内部细节，肉眼完全看不出区别。

### R2：功能精确 + 风格大方向 → 还是像

第二轮，需求改成「功能精确（API 不变）+ 风格只写'深色科技风'」。

**结果**：NEXUS 风 vs HUD 终端风——有差异，但仍是「深色科技仪表盘」这个品类。

### R3：白纸起稿 → 双双惊艳（方法论成型）

第三轮，只给**命题 + 数据源 + 验收标准**，其余全部自由：不指定形式、不指定风格、不指定布局。

**结果**：两个作品都惊艳了——pi 做出了「下午好，老板 🍵」的温暖问候语；Codex 做出了 ⌘K 命令面板和「INTERNAL OS」世界观。

### 📌 方法论结晶：需求粒度原则

> **只定义「问题 + 数据源 + 验收标准」，不定义「方案」。**
> 规划越细，AI 越平庸；留白越多，AI 越闪光。

| 应该定义（粗） | 不该定义（细） |
|---|---|
| 为什么做（痛点/场景） | 布局怎么排 |
| 给谁用（用户画像） | 什么风格 |
| 数据从哪来（文件/API） | 几个模块 |
| 怎么算好（验收标准） | 按钮放哪 |

## 三、测评设计（R3 终局）

> 时间线说明：DSH 于 2026-08-13 才开源，前两轮是 Codex 与 pi 的双雄对决；R3 时 DSH 入局，三强同台竞技。

**命题**：为果壳科技设计一个内部工具（数据源：`/data/share` 下的服务/待办/端口清单 + 系统状态 API）。形式不限、风格不限、技术 Node.js 内自由。

**同一份命题文档，同一段提示词，三个工具各自独立完成。**

**评分体系**：功能完成度 30% + 创新性 30% + 视觉交互 25% + 工程素养 15%。

**部署**：各自 push 到 Gitea，流水线自动构建部署（8084 / 8085 / 8086 端口），一次 push 自动上线。

## 六、深度分析

### 三强性格画像

- **Codex = 稳重的工程师**：功能全、代码多、模块化清晰，中规中矩不犯错。
- **pi = 效率怪兽**：最快（7 分钟）最省（59K tokens），还有产品洞察（问候语/一句话判健康）。
- **DSH = 堆料狂魔**：35 测试、SSE、Canvas 雷达、三级降级……工程深度碾压，但**交付质量差一口气**（低级 ID 冲突 bug）。

### Token 消耗的秘密

| 选手 | 输入 | 输出 | 缓存读 | 推理 |
|---|---|---|---|---|
| Codex | — | — | — | —（CLI 不显示明细） |
| pi | 24,167 | 35,094 | 450,560 | — |
| DSH | 70,170 | 208,594 | **15,697,664** | 82,762 |

- **pi 的缓存策略激进**（缓存读 45 万）——DeepSeek 缓存价格 1/10，快又省的核心秘密
- **DSH 缓存读 1570 万**——上下文管理方式导致巨量缓存命中，按 1/10 价粗算单次约 ¥4（比 pi 贵一个量级）
- 三家三轮总成本都在「块钱」级别——**DeepSeek 是真便宜**

### 方法论验证

- **给 AI 留白 = 释放设计能力**：R1 一模一样 → R3 双双惊艳，同一个模型的差距全在需求写法
- **验收机制决定行为**：测试全过 > 创新，会诱导 AI 保守；要创新就要在评分里给创新加权
- **部署配置归人管**：部署配置由莉莉预置、agent 禁碰 + 仓库自检关卡 → 三强全部一次部署上线零返工

## 七、踩坑实录（比结果更有价值）

1. **#radar ID 冲突**：DSH 版 HTML 里 section 和 canvas 同名 ID，`querySelector` 返回第一个 → `getContext` 报错 → init 中断 → 页面数据全空。排查靠「加载前注入 fetch 拦截 + 错误捕获」（CDP `Page.addScriptToEvaluateOnNewDocument`）。**教训：前端渲染错误必须前端冒烟测试**。
2. **pi 版部署错代码**：pi 复制 deploy.yml 模板时把 clone 地址写成 Codex 的仓库 → 8083 跑的是 Codex 版。**教训：部署配置归人管，agent 不碰**。
3. **搜索后端血泪史**：Hermes web_search 无 key → ddgs（DuckDuckGo 被墙）→ 必应 RSS（能用但粗糙）→ **豆包搜索**（火山引擎，每月 500 次免费，国内直连 1 秒出结果，带权威度标注）——终局方案。

## 八、结论与建议

### 怎么选？

| 场景 | 推荐 |
|---|---|
| 快速试错 / 预算敏感 | 🥇 **pi**（最快最省，效果不差） |
| 功能拉满 / 重工程 | 🆕 **DSH**（35 测试 + SSE，但要验收兜底） |
| 稳妥全面 / 生产交付 | 🤖 **Codex**（均衡不犯错） |

### 给团队的启示

1. **需求粒度 > 模型强弱**：同一个模型，详细需求做出「一模一样」，留白需求做出「双双惊艳」。
2. **token 成本不是瓶颈**：DeepSeek 全家桶一个月花不到 10 块钱——大胆用。
3. **AI 写代码，人管部署和验收**：部署配置预置 + 仓库自检 + 前端冒烟测试，是 AI 编码流程的三大护栏。
